## 확정 지시 사항

- 웹은 소비 패턴, 자산, 국내외 주식, 카드 혜택 분석과 금융 현황 관리에 집중한다. 기본 구조는 금융 대시보드와 접이식 사이드바다.
- Android 수집 대상은 Galaxy S23+에서 은행·카드 앱이 게시한 결제 알림이다. 수신한 알림은 오프라인에서도 임시 보관하고, 실패 및 장기 대기 항목은 다시 검토할 수 있어야 한다. 수신 자체가 없었던 결제는 알림 수집으로 복구할 수 없다.
- 대기 거래는 사용자가 최종 승인해야 확정된다. 자동 금융 이체, 주식 주문, 카드 발급·해지는 금지한다. 확정 원장 금액은 규칙, DB, 검증 가능한 가격·환율로 산정한다. GPT는 설명과 추천에 사용할 수 있으며 그 추론값을 원장에 반영하지 않는다.
- Android 하단 메뉴는 홈, 거래, 중앙 `+`, 카드 추천, 전체다. 중앙 `+`의 상세 UX는 보류 상태이며, 기본 수동 입력은 제안된 MVP에 포함된다. AI 비서의 모바일 플로팅 버튼 B안은 잠정이다.
- 운영은 Supabase/Vercel 무료 플랜을 중심으로 계획한다. GPT API 운영비는 연간 약 USD 5를 목표로 추적한다. Codex Pro 두 계정과 Claude의 구독비는 별도로 관리한다.
- Q20 상세 보안 정책, Q25 중앙 `+` 빠른 입력 상세 UX, Q74 영수증 원본 보관정책은 보류한다. 인증, 접근 통제, 비밀키 보호, 거래 원자성은 필수다.

### 금융 계산 규칙

- 대기는 잠정 통계에만 표시한다. 확정 소비·예산·잔액은 승인된 원장에서 계산한다. 확정 분개는 변경·삭제를 제한하고, 원본을 참조하는 역분개와 필요한 대체 거래로 정정한다. 거래별 차변·대변은 통화 또는 환산 기준 단위에서 균형을 검증한다.
- 신용카드 구매는 비용과 카드 부채를 늘린다. 카드 대금 납부는 은행 잔액과 카드 부채를 줄이며 추가 비용은 0이다. 체크카드·현금 구매는 비용을 늘리고 자산을 줄인다. 할부 구매는 매입액을 구매 시점에 비용으로 인식하고 대금 납부는 부채를 상환한다. 이자와 수수료는 별도 비용이다.
- 본인 계좌 간 이체는 순자산과 순소비를 유지한다. 이체 수수료와 대출 이자는 비용으로 처리한다. 대출 원금 이동은 자산과 부채에 반영한다.
- 투자 원금은 현금과 증권자산 사이의 이동으로 처리한다. 실현손익과 비용, 배당 현금흐름, 시가·환율에 따른 평가 변화는 각각 추적한다.
- 영수증 품목 분할 합계는 확정 구매 금액과 일치해야 한다. 지출 집계에는 구매 금액을 한 번만 반영한다. 정정 후 해당 월을 재계산하고 기존 결산 버전과 변경 이력을 보존한다.

### 웹 개발 미리보기

홈 화면은 1980×1080 데스크톱에서 확인한 Editorial Banking 레이아웃을 기준으로 한다. 콘텐츠 최대 너비는 1760px이며, 메인 열과 보조 열의 너비 비율은 약 65:35다. 샘플 홈과 Supabase 연결형 홈은 같은 레이아웃을 사용한다.

반응형 샘플 홈은 `/demo`에서 볼 수 있다. 한국 시간 기준 당월의 확정 지출과 미결제 정기 결제를 반영한 실제 남은 예산을 표시한다. 메인 열은 예산과 순자산 추이를 보여준다. 보조 열은 거래 검토, 정기 결제, 주요 소비 카테고리 순서로 배치한다. 카테고리 막대는 당월 확정 거래 필터로 연결한다. 샘플의 거래 검토, 계좌·카드 설정, 예산 설정은 각각 `/transactions?tab=review&mode=demo`, `/demo/accounts`, `/demo/budgets`에서 진행한다. 오른쪽 아래 AI 챗봇 버튼은 현재 페이지에서 금융 비서 패널을 펼친다. [Editorial Banking 홈 작업 기록](Work_Update/2026-11-26_Editorial-Banking-홈.md)

로그인 화면 구현은 프로젝트 최종 단계로 둔다. 웹 미리보기는 샘플 데이터를 브라우저에 저장하며, 대기 거래 입력·수정·선택 승인, 초기 계좌 잔액, 확정 지출 및 카테고리별 월 예산을 검토할 수 있다. 실거래를 연결하려면 인증된 사용자 세션, Supabase 스키마 검증 및 화면과 API 연결이 필요하다.

샘플 거래 검토에서 **알림 복구**를 열면 샘플 알림을 같은 브라우저의 대기 거래로 보낼 수 있다. **연결된 거래 검토**와 **연결된 알림 보기**에는 Supabase 환경 변수·마이그레이션과 기존 인증 세션이 필요하다. 연결된 거래 검토에서는 대기 거래 수정·승인과 중복 비교·제외가 가능하다. **확정 원장 집계**는 한국 시간 기준 월별 확정 순지출, 카테고리 지출과 계좌 증감을 표시한다.
Supabase가 설정된 첫 화면은 인증된 세션의 **금융 현황**을 제공한다. 이번 달 확정 순지출과 예산, 검토 대기·중복 의심 건수와 원화 합계, 원화 계좌 잔액과 최근 대조 기록을 표시한다. 비교 가능한 월말 결산으로 순자산 추이를 표시한다. 정기 결제 마이그레이션을 적용하면 확정 지출과 미결제 회차를 반영한 남은 예산을 표시한다. 환산 기준이 없는 외화 미결제 회차가 있으면 실제 남은 원화 예산은 산정 불가로 표시한다. [연결형 금융 현황 작업 기록](Work_Update/2026-11-25_연결형-금융-현황.md)

잔액 대조 이력에서 차액을 확인한 뒤 조정할 수 있다. 이체 수수료는 이체 원금과 같은 요청에서 별도 비용으로 기록한다. 확정 원장 집계에서 월별 예산과 확정 거래·분개 CSV를 사용할 수 있다. [차액 조정·이체 수수료 작업 기록](Work_Update/2026-11-25_차액-조정-및-이체-수수료.md) · [월별 예산 작업 기록](Work_Update/2026-11-25_월별-예산.md) · [원장 CSV 작업 기록](Work_Update/2026-11-25_원장-CSV-내보내기.md)

사이드바의 **월별 예산**에서 실제 남은 예산을 확인하고, 예산 현황·소비 분석·전월 비교 탭을 이용할 수 있다. 이번 달 전체 예산 설정과 지난달 배정액 복사를 지원한다. [월별 예산 탭 개편 작업 기록](Work_Update/2026-11-26_월별-예산-탭-개편.md)

**계좌·카테고리 설정**에서 연결된 원화 결제 계좌와 비용 카테고리를 등록한다. **연결된 거래 검토 → 구매 입력**에서 수동 구매를 대기 거래로 만들 수 있다. [설정·구매 입력 작업 기록](Work_Update/2026-11-25_연결된-계좌-설정-및-구매-입력.md)

대기 거래의 **분할**에서 금액을 여러 카테고리에 배분할 수 있다. 부분 환불은 각 카테고리의 남은 금액에 비례해 반영한다. **가맹점 분류 규칙**은 새 구매를 입력할 때 사용자가 정의한 카테고리를 제안한다. [분할 구매·환불 작업 기록](Work_Update/2026-11-25_분할-구매-및-환불.md) · [가맹점 분류 규칙 작업 기록](Work_Update/2026-11-25_가맹점-분류-규칙.md)

**연결된 거래 검토 → 확정 → 환불·정정**에서 잘못 입력한 구매를 정정할 수 있다. 원본은 보존하고 구매일에 역분개를 기록한다. 금액이나 분류를 바로잡을 때는 정정 후 새 구매를 입력한다. [확정 구매 정정 작업 기록](Work_Update/2026-11-25_확정-구매-정정.md)

**카드 할부 계획**은 확정된 원화 신용카드 구매의 원금과 예상 수수료를 월별로 표시한다. 구매 원장은 구매일에 전체 비용을 기록하고, 실제 카드 대금 납부는 부채를 상환한다. **카드 혜택**에서는 보유 카드의 정률 혜택 약관을 버전별로 저장하고, 카드사 명세서에서 확인한 실적을 입력해 예상 혜택을 계산할 수 있다. [할부 작업 기록](Work_Update/2026-11-25_카드-할부-청구-계획.md) · [카드 혜택 작업 기록](Work_Update/2026-11-25_카드-약관-및-예상-혜택.md)

영수증 품목 API는 사용자가 확인한 품목·할인·포인트·배송비를 검토 대기 구매에 연결하고 카테고리 금액을 생성한다. 월말 결산 API는 마감한 달의 지출·예산·원화 계좌 잔액을 버전으로 저장하며 이후 원장과 비교할 수 있다. [영수증 작업 기록](Work_Update/2026-11-25_영수증-품목-및-할인.md) · [월말 결산 작업 기록](Work_Update/2026-11-25_월말-결산-버전.md)

원화 구매 CSV는 지정 양식으로 최대 100건을 한 번에 검토 대기에 추가한다. 재전송한 파일의 정규화된 내용과 행 순서가 같으면 기존 거래 ID를 반환한다. [CSV 가져오기 작업 기록](Work_Update/2026-11-25_구매-CSV-가져오기.md)

### 출시 단계와 검증

- **Phase 0**은 계정·원장·이벤트·대기 모델, RLS, 승인·수집 원자성, Android API 계약을 다룬다. 사용자 간 데이터 격리와 실패 시 롤백으로 안전성을 확인한다.
- **Phase 1**은 로그인, 초기 잔액, 기본 거래·분류·예산, KRW 금융 흐름, Android 수집과 거래 검토 센터, 기본 내보내기와 오류 모니터링을 다룬다. 정량 분개 검증과 실제 기기에서의 전체 흐름을 출시 조건으로 삼는다.
- **Phase 2**는 카드 실적·혜택·추천, 주식·ETF·배당·환율, 잔액 대조·월말 결산, 고급 예산과 보고서를 다룬다.
- **Phase 3**은 약관 자동 갱신, AI 상담·자동화·자연어 검색, 고급 투자 분석, OCR·품목 분할을 다룬다. 추정치에는 출처와 기준 시점을 제공한다.

점검서의 협업 제안은 서버·웹 담당이 DB와 API 계약을 관리하고, Android 담당이 계약에 맞춰 수집·로컬 큐·재전송을 구현하며, 별도 검토에서 회계 정확성·권한·데이터 노출을 확인하는 방식이다. 통합 시 브랜치별 변경과 CI 결과를 확인한다.
