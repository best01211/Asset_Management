## 확정 지시 사항

- 웹은 소비 패턴, 자산, 국내외 주식, 카드 혜택 분석과 금융 현황 관리에 집중한다. 기본 구조는 금융 대시보드와 접이식 사이드바다.
- Android 수집 대상은 Galaxy S23+에서 은행·카드 앱이 게시한 결제 알림이다. 수신한 알림은 오프라인에서도 임시 보관하고, 실패 및 장기 대기 항목은 다시 검토할 수 있어야 한다. 수신 자체가 없었던 결제는 알림 수집으로 복구할 수 없다.
- 대기 거래는 사용자가 최종 승인해야 확정된다. 자동 금융 이체, 주식 주문, 카드 발급·해지는 금지한다. 확정 원장 금액은 규칙, DB, 검증 가능한 가격·환율로 산정한다. GPT는 설명과 추천에 사용할 수 있으며 그 추론값을 원장에 반영하지 않는다.
- Android 하단 메뉴는 홈, 거래, 중앙 `+`, 카드 추천, 전체다. 중앙 `+`의 상세 UX는 보류 상태이며, 기본 수동 입력은 제안된 MVP에 포함된다. AI 비서의 모바일 플로팅 버튼 B안은 잠정이다.
- 운영은 Supabase/Vercel 무료 플랜을 중심으로 계획한다. GPT API 운영비는 연간 약 USD 5를 목표로 추적한다. Codex Pro 두 계정과 Claude의 구독비는 별도로 관리한다.
- Q20 상세 보안 정책, Q25 중앙 `+` 빠른 입력 상세 UX, Q74 영수증 원본 보관정책은 보류한다. 인증, 접근 통제, 비밀키 보호, 거래 원자성은 필수다.

### 금융 계산 규칙

- 대기는 잠정 통계에만 표시한다. 확정 소비·예산·잔액은 승인된 원장에서 계산한다. 확정 분개는 변경·삭제를 제한하고, 원본을 참조하는 역분개와 필요한 대체 거래로 정정한다. 거래별 차변·대변은 통화 또는 환산 기준 단위에서 균형을 검증한다.
- 신용카드 구매는 비용과 카드 부채를 늘린다. 카드 대금 납부는 은행 잔액과 카드 부채를 줄이며 추가 비용은 0이다. 체크카드·현금 구매는 비용을 늘리고 자산을 줄인다. 할부 구매는 매입액을 구매 시점에 비용으로 인식하고 대금 납부는 부채를 상환한다. 이자와 수수료는 별도 비용이다.
- 본인 계좌 간 이체는 순자산과 순소비를 유지한다. 이체 수수료와 대출 이자는 비용으로 처리한다. 대출 원금 이동은 자산과 부채에 반영한다.
- 투자 원금은 현금과 증권자산 사이의 이동으로 처리한다. 실현손익과 비용, 배당 현금흐름, 시가·환율에 따른 평가 변화는 각각 추적한다.
- 영수증 품목 분할 합계는 확정 구매 금액과 일치해야 한다. 지출 집계에는 구매 금액을 한 번만 반영한다. 정정 후 해당 월을 재계산하고 기존 결산 버전과 변경 이력을 보존한다.

첫 구현은 **확정 원장 불변성과 승인 원자성**이다. 여기에 계정 검증과 사용자별 접근 통제를 포함한다. 오프라인 알림의 저장·재전송 계약은 이 단계와 함께 설계하고, Android와 웹 연동 전에 API 계약을 확정한다.

### 출시 단계와 검증

- **Phase 0**은 계정·원장·이벤트·대기 모델, RLS, 승인·수집 원자성, Android API 계약을 다룬다. 사용자 간 데이터 격리와 실패 시 롤백으로 안전성을 확인한다.
- **Phase 1**은 로그인, 초기 잔액, 기본 거래·분류·예산, KRW 금융 흐름, Android 수집과 거래 검토 센터, 기본 내보내기와 오류 모니터링을 다룬다. 정량 분개 검증과 실제 기기에서의 전체 흐름을 출시 조건으로 삼는다.
- **Phase 2**는 카드 실적·혜택·추천, 주식·ETF·배당·환율, 잔액 대조·월말 결산, 고급 예산과 보고서를 다룬다.
- **Phase 3**은 약관 자동 갱신, AI 상담·자동화·자연어 검색, 고급 투자 분석, OCR·품목 분할을 다룬다. 추정치에는 출처와 기준 시점을 제공한다.

점검서의 협업 제안은 서버·웹 담당이 DB와 API 계약을 관리하고, Android 담당이 계약에 맞춰 수집·로컬 큐·재전송을 구현하며, 별도 검토에서 회계 정확성·권한·데이터 노출을 확인하는 방식이다. 통합 시 브랜치별 변경과 CI 결과를 확인한다.
