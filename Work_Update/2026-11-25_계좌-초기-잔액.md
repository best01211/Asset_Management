# 2026-11-25 계좌 초기 잔액

## 목적과 관련 항목

Q5, Q51, Q53과 점검서 C-4의 초기 잔액 기준을 구현했다. 초기 잔액은 기록한 기준 시각 직전의 계좌 상태로 취급하며, 그 시각부터 현재까지의 확정 구매를 반영한다.

## 변경 내용

- `supabase/migrations/20261125021113_record_account_opening_balances.sql`을 추가했다. 원화 자산과 부채의 초기 잔액을 자본 계정과 복식 분개하고 0원은 기준 기록만 남긴다. 같은 값의 재시도는 기존 기록을 반환하고 다른 값으로 다시 등록하는 요청은 충돌로 처리한다.
- 초기 잔액 및 분개의 불변성을 유지한다. 조회 시 초기 잔액 미등록을 0원과 구분하며, 초기 잔액 자체는 구매 지출에서 제외한다.
- `/api/account-balances`와 계좌 잔액 화면을 추가했다. **확정 원장 집계 → 계좌 잔액**에서 초기 잔액을 등록하고 확정 구매 증감과 계산 잔액을 조회한다.
- README, API 계약, 검증 절차를 갱신했다. 로그인 화면 구현은 최종 단계로 유지했다.

## 검증 결과와 남은 작업

격리 PostgreSQL 17.12에서 SQL 테스트 9개를 통과했다. 자산·부채 차변 및 대변 방향, 0원, 기준 시각, 미확정·미래 거래 제외, 중복 요청, 원장 불변성, 다른 사용자 격리와 구매 집계 제외를 확인했다. Next.js 빌드와 TypeScript 검사도 통과했다.

테스트용 Supabase 연결에서 브라우저로 초기 잔액 100,000원을 등록하고, 기준 시각 이후 확정 구매 4,000원이 반영된 계산 잔액 96,000원이 표시되는 것을 확인했다. 새로고침 후에도 저장된 잔액이 표시되고 같은 계좌에 초기 잔액 등록 버튼은 사라졌다.

실제 잔액 입력과 대조 이력, 차액 조정, 카드 대금 납부·이체·환불은 후속 작업이다. 이번 변경은 로컬 작업이다.
