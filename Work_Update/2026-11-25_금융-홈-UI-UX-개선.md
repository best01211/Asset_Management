# 금융 홈 UI·UX 개선

## 화면 변경

- 보라색 사이드바와 밝은 배경, 흰색 패널, 기존 홈 정보 순서를 유지했다. 데스크톱에서는 예산과 검토, 순자산과 카테고리를 옆에 배치한다. 좁은 화면은 한 열로 표시한다.
- 월 예산에서 확정 지출을 뺀 현재 잔액과 정기 결제까지 반영한 가용 예산을 구분했다. 확정 지출은 단색, 예정 지출은 패턴으로 표시하고 계산식을 펼쳐 확인할 수 있다.
- 대기 건수와 전체 대기 금액, 전용 거래 검토 링크를 상단에 표시한다. 샘플 홈은 최근 대기 거래를 최대 3건 표시한다.
- 카테고리 막대에 이름·금액·비율을 정렬하고 클릭 시 당월 확정 거래로 이동한다. 연결형 원장에서는 분할 구매와 카테고리별 환불 배분, 정정 구매 제외, 이체 수수료를 기존 집계 기준으로 반영한다.
- 예정 결제에는 예정일, D-Day, 금액과 이번 달 남은 합계를 표시한다. 대기 상태는 확정 지출 집계에 포함되지 않는다.

## 데이터 기준

- 샘플 순자산은 기존 초기 잔액과 확정 거래로 계산 가능한 날짜만 표시한다. 저장된 샘플의 예전 임의 보정 금액은 차트에서 제외했다.
- 연결형 순자산은 현재 원화 원장과 저장된 월말 결산으로 계산한다. 계좌 집합과 잔액이 모두 확인되는 비교점이 있을 때 전월 말 대비 증감액과 증감률을 표시한다. 잔액 대조 기록과 비어 있는 기간은 별도로 안내한다.
- 연결형 정기 결제 전용 일정 데이터는 아직 없다. 해당 일정과 가용 예산의 데이터 상태를 표시한다. 샘플 홈의 예정 결제는 브라우저에 저장한다.
- Supabase 사용자 세션, 기존 API, RLS와 라우트를 사용한다. 화면 연결 상태는 실제 조회 결과에 따라 표시한다.

## 검증

- 로컬 브라우저에서 데스크톱 2열, 모바일 1열, 메뉴 접기, 예산 산식, 순자산 기간·변동 내역, 당월 카테고리 필터를 확인했다.
- 카테고리 분할·환불·정정·수수료와 월말 날짜 경계를 확인했다. 기존 로컬 DB 마이그레이션 23개, SQL 테스트 25개, 백업·복원, 사용자 격리를 검증했다.
- `npm run typecheck`, `npm run lint`, `npm run build`를 통과했다. 타입 검사는 TypeScript 7, ESLint는 TypeScript 6 호환 API를 사용한다. Windows 기본 빌드는 junction 생성 권한이 있는 환경에서 완료했다.
- 로컬 브라우저는 샘플 화면으로 검증했다. 원격 Supabase의 인증된 사용자 데이터 화면은 확인하지 못했다.
