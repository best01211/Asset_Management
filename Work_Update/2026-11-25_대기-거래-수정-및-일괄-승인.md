# 2026-11-25 대기 거래 수정 및 일괄 승인

## 목적과 관련 항목

Q3, Q65~Q68과 점검서 C-7의 대기 거래 수정 및 선택 일괄 승인을 연결했다. 로그인 화면은 최종 작업으로 보류하고 기존 인증 경계를 사용했다.

## 변경 내용

- `supabase/migrations/20261125014744_edit_pending_expenses.sql`에 버전 확인을 포함한 수정 RPC를 추가했다. 수정과 승인에 같은 거래 행 잠금을 사용한다. 실제 변경이 있을 때만 버전을 올리고 변경 전후 내용을 감사 로그에 남긴다. 알림이 재전송되면 저장된 원래 후보를 비교해 수동 수정 내용을 유지한다.
- `PATCH /api/pending-transactions/{id}`와 계좌·카테고리 조회 API를 추가했다. 거래 목록은 편집에 필요한 계좌·카테고리 ID도 반환한다. 연결된 알림 복구 화면과 거래 편집은 같은 계좌·카테고리 조회 로직을 사용한다.
- `POST /api/pending-transactions/batch-approve`가 최대 20건을 각각 독립적으로 승인하고 입력 순서대로 결과를 반환한다. 단건과 일괄 승인에 같은 승인 RPC 및 오류 처리를 사용한다.
- 거래 검토 화면에 수정 폼, 선택 항목 확인, 일괄 승인 버튼, 항목별 결과를 추가했다. 결과가 불확실한 재시도에는 같은 거래 버전의 요청 키를 재사용한다.
- README, API 계약, DB 테스트 절차를 갱신했다.

## 검증 결과

- PostgreSQL 17.12에서 SQL 테스트 6개를 통과했다. 변경 없는 저장, 다른 사용자 수정 차단, 잘못된 계좌 거절, 변경 이력, 기존 알림 재전송 후 수정 유지, 이전 버전 승인 충돌, 수정 금액으로 원장 확정을 확인했다. 기존 동시 승인과 동시 알림 수집 검증도 통과했다.
- Next.js 프로덕션 빌드와 TypeScript 검사를 통과했다.
- 테스트용 Supabase 연결에서 브라우저로 가맹점·금액·결제수단을 수정하고, 금액 정밀도와 수정하지 않은 거래 시각의 소수 초가 유지되는 것을 확인했다. 한 번의 일괄 요청에서 한 건 확정과 한 건 충돌을 각각 표시했고, 확정한 건만 확정 목록에 나타났다.

## 남은 작업

중복 의심 거래의 연결과 사용자 확인 처리, 실제 원장 집계, 운영 Supabase 검증이 남아 있다. 이번 변경은 로컬 작업이다.
