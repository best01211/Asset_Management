# 2026-11-25 알림 수집 및 복구

## 목적과 관련 항목

Q1, Q19, Q66~Q71과 점검서 C-1·C-2를 기준으로 재전송 중복을 막고 파싱에 실패한 이벤트를 나중에 복구할 수 있도록 했다. 새 경로의 수집 필드는 C-10에 맞춰 제한했다.

## 변경 내용

- `supabase/migrations/20261125011909_recoverable_notification_ingestion.sql`에서 이벤트 기록과 거래 후보 생성을 하나의 RPC로 처리한다. 이벤트 행을 잠그고, 이미 후보가 있으면 기존 ID를 반환한다. 같은 이벤트 ID에 출처·수신 시각·후보 데이터가 달라지면 충돌을 반환한다.
- 파싱이 실패하면 금액이나 계좌 정보 없이도 이벤트와 오류 코드를 저장한다. 계좌·카테고리를 잘못 지정한 경우도 복구 목록에서 볼 수 있다. 같은 이벤트로 파싱 결과를 다시 제출해 성공하면 복구 목록에서 제외된다.
- `src/app/api/notification-events/route.ts`에 수집·재제출 `POST`와 페이지 단위의 복구 목록 `GET`을 추가했다. 웹 쿠키 세션과 모바일 사용자 Bearer 토큰을 지원한다. 새 수집 요청은 알림 원문이나 추가 필드를 허용하지 않는다.
- `supabase/tests/005_notification_recovery.sql`에 중복 재전송, 복구, 이벤트 키 충돌, 개인정보 필드 제한, 사용자 격리, 후보 생성 오류 시 롤백 테스트를 추가했다. README, API 계약, 검증 로드맵을 갱신했다.

## 검증 결과

- 격리 PostgreSQL 17.12에서 마이그레이션 세 개와 기존·신규 SQL 테스트 다섯 개를 통과했다. 별도 세션 두 개가 같은 이벤트를 동시에 제출해도 이벤트와 대기 후보가 각각 한 건만 생성됐다.
- Next.js 프로덕션 빌드와 타입 검사를 통과했다. 테스트용 Supabase 응답을 사용해 HTTP 인증 헤더 전달, 실패 기록 응답, 충돌 상태 코드, 복구 목록 페이지 이동을 확인했다.
- 운영 Supabase, Galaxy S23+ 실기기, 실제 은행·카드 앱 알림은 미검증이다.

## 남은 작업

Android 수집·로컬 큐 및 웹 복구 화면을 새 API에 연결한다. 기존 수신 RPC의 자유 형식 payload는 호환을 위해 남아 있다. 기기 측 원문 보호·보관 주기, 은행·카드 앱 허용목록, 실제 결제 중복 판별은 후속 작업이다.
