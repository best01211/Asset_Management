# 2026-11-25 연결된 거래 검토

## 목적과 관련 항목

Q2~Q4, Q26~Q27, Q66~Q68의 거래 검토 중 Supabase에 저장된 대기 거래 조회와 건별 승인을 연결했다. 로그인 화면 구현은 프로젝트의 최종 단계로 보류한다.

## 변경 내용

- `GET /api/pending-transactions`를 추가했다. 현재 인증 세션과 RLS가 허용한 거래만 검토 대기·중복 의심·확정 상태별로 조회한다. 카테고리와 계좌 이름, 거래 시각, 금액, 승인 버전을 반환하고 페이지를 거래 시각과 ID로 구분한다. 원화 금액을 문자열로 전송해 큰 정수의 정밀도를 유지한다.
- `src/app/transaction-review/`에 거래 목록과 승인 확인 화면을 만들었다. 기존 단건 승인 API를 사용하며, 응답을 확인할 수 없을 때 새로고침 후에도 같은 버전의 요청 키로 재시도한다. 충돌이 나면 최신 목록을 다시 읽는다.
- 대시보드의 거래 검토와 연결된 알림 복구 화면에 **연결된 거래 검토** 링크를 추가했다. 연결된 알림의 복구 직후 **대기 거래 확인**을 열 수 있다.
- 루트 README와 API 계약에 연결된 거래 검토 경로와 응답 형식을 반영했다.

## 검증 결과

- Next.js 프로덕션 빌드와 TypeScript 검사를 통과했다. 격리 PostgreSQL에서 기존 SQL 테스트 다섯 개와 조회에 사용하는 계좌·카테고리 외래 키를 확인했다.
- 로컬 테스트용 Supabase 응답을 사용한 브라우저에서 비인증 접근 안내, 목록 다음 페이지와 큰 원화 금액 표시, 응답 실패 후 새로고침을 거친 승인 재시도, 승인 충돌 후 새로고침, 확정 목록 반영, 중복 의심 거래의 승인 버튼 미표시를 확인했다.
- 운영 Supabase와 실제 사용자의 인증 세션은 미검증이다. 이번 변경은 로컬 작업이다.

## 남은 작업

연결된 대기 거래의 수정과 선택 일괄 승인, 중복 검토 처리를 이어간다. 대시보드의 집계는 샘플 모드이며 실제 원장 집계 연동이 남아 있다.
