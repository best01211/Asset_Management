# 영수증 품목과 할인 배분

2026-11-25 · 로컬 데이터 모델과 API

- 검토 대기 구매에 사용자가 확인한 품목을 연결한다. 품목 할인과 주문 할인·포인트·배송비를 포함한 합계가 실제 결제액과 일치해야 저장된다.
- 개별 할인 후 금액 비율로 결제액을 배분한다. 원 미만 나머지가 큰 순서와 입력 순서로 배분 차이를 맞춘다. 이렇게 만든 카테고리 분할은 기존 구매 승인·환불·예산 흐름을 사용한다.
- 품목과 분할은 함께 저장되고 대기 거래의 버전이 바뀐다. 확정 이후 품목과 원본 연결을 보존한다.
- 사용자 검토가 끝난 OCR 결과를 입력할 수 있다. 원본 파일 저장, OCR 실행, 특정 품목만 반품했을 때의 지정 배분은 후속 범위다.

## 검증

- 격리 PGlite에서 10,001원 구매의 원 단위 배분, 무상 품목 보존, 결제액 불일치, 수동 분할 충돌, 승인 후 변경 제한, 원장 중복 방지와 카테고리별 부분 환불을 검증했다.
- 로컬 프로덕션 서버에서 격리 DB에 연결한 테스트 API로 결제액 불일치 요청의 422 응답과 품목 저장·조회를 확인했다. TypeScript 검사와 프로덕션 빌드를 통과했다.
