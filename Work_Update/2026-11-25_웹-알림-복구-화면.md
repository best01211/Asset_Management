# 2026-11-25 웹 알림 복구 화면

## 목적과 관련 항목

Q2~Q4, Q67, Q71의 웹 복구 흐름을 구현했다. 로그인 화면은 이후에 작업하며, 샘플 데이터로 먼저 거래 대기 흐름을 확인할 수 있다.

## 변경 내용

- `src/app/notification-recovery/`에 복구 대기 목록, 실패 사유와 수신 시각, 가맹점·금액·거래 시각·결제 계좌·카테고리 보완 폼을 추가했다. 신용카드에는 부채 계좌를, 체크카드·현금에는 자산 계좌를 제시한다.
- 대시보드 메뉴와 거래 검토에 **알림 복구** 진입점을 추가했다. 샘플 복구는 같은 브라우저의 대기 거래 목록에 저장되며 승인 전 집계에는 반영되지 않는다.
- **연결된 알림 보기**는 기존 Supabase 웹 세션 검증 후 계좌·카테고리를 조회한다. 기존 복구 API로 목록을 읽고, 같은 이벤트 정보와 입력한 거래 내용을 재제출한다. 복구에 성공하면 해당 알림을 목록에서 제외하고 Supabase 대기 거래를 유지한다.
- `src/lib/notification-recovery.ts`, `src/lib/local-finance.ts`에 복구 데이터 타입과 샘플 저장 연결을 추가하고, 루트 README에 진입 경로를 기록했다.

## 검증 결과

- Next.js 프로덕션 빌드 및 TypeScript 검사 통과.
- 브라우저에서 샘플 알림 복구, 결제 수단별 계좌 필터, 대기 목록 반영, 승인 전 확정 지출 유지와 새로고침 후 단건 유지 확인.
- 로컬 테스트용 Supabase 응답으로 인증 세션이 없을 때 접근 안내가 표시되고, 테스트 세션에서 계좌·목록 조회와 복구 제출이 완료되는 것을 확인했다. 복구 요청이 최초 수신 시각을 유지하고 거래 시각을 초 단위까지 보내는 것도 확인했다.
