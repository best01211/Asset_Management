# 2026-11-25 잔액 대조 및 주요 금융 거래

## 목적과 관련 항목

Q5~Q6, Q17, Q51~Q53과 점검서 C-4·Gate B에 따라 동일 시각의 실제 잔액 대조와 원화 카드 대금 납부, 본인 계좌 이체, 구매 환불을 연결했다.

## 변경 내용

- `supabase/migrations/20261125021742_reconcile_accounts_and_post_movements.sql`에서 조회 시각의 초기 잔액과 확정 분개를 합산한다. 대조 입력은 실제 잔액, 당시 원장 잔액, 확인 시각을 저장하고 차이를 반환한다. 후속 입력이 저장된 대조 이력을 바꾸지 않는다.
- 납부는 자산과 카드 부채를 감소시킨다. 본인 계좌 이체는 두 자산 계좌 사이의 원금 이동이다. 두 거래 모두 지출에서 제외한다.
- 환불은 원본 구매의 결제 계좌와 비용 계정에 반대 분개를 기록한다. 누적 부분 환불의 한도는 원본 구매액이다. 월간 지출 및 카테고리에서는 환불 처리 월에 원본 카테고리에서 차감한다. 현재 단일 카테고리 구매를 지원한다.
- `/api/account-activity`와 로컬 연결 화면을 추가했다. **계좌 잔액 → 계좌 대조 및 거래 기록**에서 대조·납부·이체를 입력하고, **연결된 거래 검토 → 확정 → 환불 기록**에서 원본 구매를 선택한다.
- README, API 계약, 검증 절차를 갱신했다. 로그인 구현은 최종 단계로 두고 변경 사항은 로컬에 유지했다.

## 검증

- PostgreSQL 17.12 SQL 테스트 10개와 Next.js 빌드·타입 검사를 통과했다.
- 과거 시각의 실제 잔액 대조와 이후 거래 반영, 납부·이체의 지출 제외, 다음 달 부분 환불, 요청 재시도, 사용자 격리를 확인했다.
- 별도 DB 세션에서 같은 원본의 두 부분 환불이 동시에 진행되는 경우 하나만 반영되고 두 번째는 누적 한도를 초과해 거절되는 것을 확인했다.
- 테스트용 Supabase 연결에서 브라우저로 대조 기록과 차액 표시, 카드 대금 납부, 본인 계좌 이체, 원본 구매의 부분 환불 양식을 확인했다.

## 남은 작업

대조 차액의 조정 승인, 이체 수수료, 다중 카테고리 환불과 실제 Supabase 프로젝트에서의 통합 검증은 남아 있다.
