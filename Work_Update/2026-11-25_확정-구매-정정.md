# 확정 구매 기록 정정

2026-11-25 · 로컬 구현

- 연결된 거래 검토의 확정 구매에서 원본을 확인하고 정정 사유를 저장한다. 차변과 대변을 모두 뒤집은 전표를 원본 구매일에 기록한다. 원본 거래·분개·분할과 정정 사유는 보존한다.
- 정정된 구매는 구매 건수, 소비 합계, 예산에서 제외된다. 계좌 잔액에는 원본과 역분개가 함께 반영된다. 원장 CSV에서 정정의 원본 ID를 추적할 수 있다.
- 같은 구매와 사유로 다시 요청하면 기존 정정 ID를 반환한다. 원본을 잠그는 방식으로 환불과 정정을 직렬화한다. 현재 정정 대상은 환불 이력이 없는 구매다. 필요한 경우 거래 검토에서 대체 구매를 입력한다.

## 검증

- 격리 PGlite에서 마이그레이션 15개와 SQL 테스트 17개를 실행했다. 다중 카테고리 역분개, 기존 원장 보존, 정정 후 요약·CSV, 반복 요청, 환불과 정정의 상호 제한, 사용자별 데이터 격리를 확인했다.
- TypeScript 검사와 Next.js 프로덕션 빌드를 통과했다.
- 브라우저와 로컬 테스트용 API에서 정정 사유 저장, 새로고침 후 사유 표시, 정정 이후 환불 버튼 비활성화를 확인했다.
