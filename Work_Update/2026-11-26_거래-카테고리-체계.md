# 거래 카테고리 체계

2026-11-26 · Q15–Q16, Q54–Q57, Q65, Q73

- 지출 대분류 11개와 소분류 62개, 수입 대분류 3개와 소분류 16개, 추천 태그 10개를 사용자별로 초기화한다. 예전 카테고리는 원래 이름과 UUID를 보존하고 기존 지출 아래에서 조회한다.
- 기존 `categories`의 소분류 참조를 재사용하고 대분류와 거래 유형 일치를 복합 외래키로 검증한다. 확정 원장의 카테고리·분개 참조는 그대로 유지한다. 사용자가 확인한 재분류는 별도 분류 이력과 감사 로그로 기록하며, 구매·관련 환불·이체 수수료의 카테고리별 보고에 반영한다.
- 관리 화면에서 대분류 이름, 소분류 이름·표시 순서, 사용자 소분류 사용 상태를 변경하고 태그를 추가·변경·삭제한다. 사용을 중지하기 전 거래·예산·규칙 연결 수를 보여준다. 기본 카테고리는 삭제나 비활성화 없이 유지한다.
- 복수 태그를 저장하는 기존 `transaction_annotations.tags`를 재사용한다. 태그 목록은 검색과 관리에 쓰며, 이름 변경 및 삭제 시 연결 거래의 태그와 수정 이력을 같은 트랜잭션에서 갱신한다.
- 거래 입력은 수동 지정, 저장된 가맹점 규칙, 반복해서 동일하게 확정된 거래, 미분류 순으로 표시한다. 추천은 대기 화면에서 확인할 수 있다. 정기 결제, 이체, 환불 및 취소는 카테고리와 독립된 속성 또는 원장 거래 유형으로 유지한다.
- 기존 원장의 실제 분류 변경은 거래별 확인 후에만 반영한다. 외부 가계부의 자동 변환, 외부 AI 추천, 연결형 정기 결제 관리 기능은 이 변경에 연동하지 않았다. 운영 환경에는 새 마이그레이션 적용이 필요하다.

## 검증

- 프로덕션 빌드에서 TypeScript 검사를 통과했고 ESLint를 실행했다.
- 로컬 DB에서 마이그레이션 25개와 SQL 테스트 27개를 통과했다. 기본 생성의 재실행 안전성, 사용자 격리, 이름·순서·비활성화, 태그 변경 감사 기록, 추천 우선순위를 확인했다. 확정 구매를 다른 분류로 옮긴 뒤 원장과 순지출이 같고, 관련 환불이 한 번만 차감되는 것을 확인했다.
- 1980×1080 Edge에서 로컬 Supabase 응답을 사용해 지출·수입 분리, 소분류 추가와 사용 중지 영향 확인, 태그 편집·삭제, 계층 검색, 거래별 이동을 확인했다.

## 거래 목록 태그 표시

- 확정 내역의 거래명 아래에 태그를 최대 2개 표시한다. 나머지는 개수로 표시하고, 전체 태그는 거래 상세에서 확인한다. 목록은 태그 저장 결과를 바로 반영한다.
- 1980×1080 Edge에서 태그 두 개, 추가 개수, 태그가 없는 행, 저장 직후 목록 갱신을 확인했다. 프로덕션 빌드와 변경 컴포넌트 ESLint를 통과했다.

## 설정 창으로 이동

- 홈과 거래 화면의 상단 설정 버튼으로 카테고리·태그 관리 창을 연다. 사이드바의 계좌·카테고리 설정 메뉴는 제거했고, 설정 창에서 계좌 설정과 가맹점 규칙으로 이동할 수 있다.
- 기존 카테고리 관리 URL은 설정 창을 바로 여는 경로로 리디렉션한다. 거래 목록·탭·상세 동작은 기존 구현을 사용한다.
- 프로덕션 빌드와 ESLint를 통과했다. 1980×1080 Edge에서 홈·거래 진입, 거래 URL을 유지한 설정 열기, 닫기 후 포커스 복귀, 기존 링크 연결과 카테고리·태그 관리를 확인했다.
