# 정기 결제 관리

2026-11-26 · 정기 결제, Q9 알림, 거래 승인 및 월간 예산 연동

## 변경

- `/recurring-payments`와 독립 사이드바 메뉴를 추가했다. 월 이동, 통화별 요약, 날짜순 타임라인, 검색·필터, 서비스 상세와 신규 등록 모달을 제공한다.
- 서비스 버전, 개별 회차, 확정 거래 연결, 웹 알림을 분리했다. 상태 변경은 적용일 이후 회차에 반영한다. 매주, 매월, 매년, 일 또는 월 단위 사용자 지정 주기를 지원한다. 월말 기준일이 없는 달은 마지막 날로 처리한다.
- 승인된 구매에 한해 결제 계좌·통화·금액이 같고 정규화된 가맹점명 또는 별칭이 예정일 전후 2일 안의 단일 회차와 일치할 때 자동 연결한다. 이름과 기간이 겹치거나 금액이 다른 경우 확인 대상으로 남긴다. 확정 거래는 한 회차에만 연결할 수 있다.
- 사용자는 회차를 확인한 후 확정 거래를 수동 연결하거나 해제할 수 있다. 일부 결제는 실제 연결분만 예정액에서 차감하고, 사용자가 완료로 확정한 회차는 실제액과 예상액이 달라도 남은 예정액을 0으로 처리한다. 정정된 원장 거래의 연결 이력은 보존하지만 유효 결제액에는 포함하지 않는다.
- 연결형 홈에서는 같은 사용자 잠금에서 확정 원장 요약과 예정 회차를 읽고, 미결제분만 예산에서 차감한다. 환산 기준이 없는 외화 예정액은 통화별로 표시한다.
- 웹 알림은 애플리케이션 내에서 표시하며 회차·종류·기준일의 고유 제약으로 중복을 방지한다. 알림 링크는 해당 월과 서비스·회차를 선택하고 읽음 상태를 기록한다.

## 외부 연동

- 프로젝트에 Android 앱, 푸시 토큰 등록·발송 백엔드 또는 백그라운드 스케줄러가 없다. 서비스별 푸시 설정은 저장된다. 웹 알림은 앱을 열 때 생성되며, 브라우저를 닫았을 때의 푸시 발송과 로그인 복귀 흐름은 별도 연동 대상이다.
- 운영 Supabase에는 신규 정기 결제 마이그레이션 적용이 필요하다.

## 화면 다듬기 및 탭 통합

- 데스크톱에서 왼쪽 일정·목록과 오른쪽 상세 패널의 시작 높이를 맞췄다. 상세는 예상 결제액, 회차 관리, 알림·이력, 서비스 상태 관리 순서로 구성했다.
- **결제 일정**과 **전체 서비스**를 탭으로 묶었다. 기본 탭은 결제 일정이다. 같은 날짜의 회차는 한 그룹으로 표시하고 가장 가까운 미결제 회차를 강조한다.
- 두 탭에서 오른쪽 상세 패널을 공유하며 선택한 서비스와 회차를 유지한다. 전체 서비스에서는 검색·필터와 함께 등록된 카드나 계좌를 **결제 수단** 열에서 확인한다. 설정이 없으면 `미지정`을 표시한다.
- 화면 변경은 `src/app/recurring-payments`의 작업 화면, 상세 컴포넌트, 스타일에 반영했다. Edge 1980px와 390px에서 탭·키보드 전환, 검색·필터, 결제 수단 표시, 서비스 상태 변경, 거래 연결과 전역 챗봇 위치를 확인했다.

## 검증

- TypeScript, ESLint와 Next.js 프로덕션 빌드를 통과했다.
- 로컬 DB에서 마이그레이션 26개와 SQL 테스트 28개를 통과했다. 월말·연간 일정, 회차 중복 방지, 사용자별 RLS, 승인 후 자동 연결, 금액 불일치와 충돌, 일부 결제, 일시중지·재활성화·해지, 이력 보존, 일정 변경 시 기존 알림 제외, 예산 중복 차감 방지를 검증했다.
- Edge 1980×1080 및 390px에서 로컬 SQL 함수에 연결해 등록·일시중지·확정 거래 연결·웹 알림에서 상세 이동·홈 예산과 기존 거래 화면을 확인했다. 운영 Supabase와 Android 발송 검증은 별도다.
