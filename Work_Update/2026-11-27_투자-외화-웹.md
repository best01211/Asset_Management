# 투자·외화 웹 화면

2026-11-27 · Q7~Q9, Q43~Q50 · 투자 거래 기록과 외화 현금 관리

## 화면과 파일

- `src/app/investments/[[...view]]/page.tsx`와 `workspace.tsx`는 투자·외화 요약, 보유 테이블, 선택 자산, 분석, 종목 상세와 전체 거래 관리를 제공한다. `entry-form.tsx`는 거래 등록·정정, `analytics.tsx`는 자산 비중·성과·거래 검색·가격 차트를 담당한다. `investments.css`는 기존 디자인 토큰과 Pretendard를 사용한다.
- `src/app/dashboard.tsx`와 `src/lib/finance-navigation.ts`에서 기존 메뉴를 연결했다. `/investments?mode=demo`는 브라우저 전용 샘플이다. 연결 모드의 읽기와 쓰기는 `src/app/api/investments/workspace/route.ts`를 사용한다. 탭과 선택 자산은 URL에 반영된다.
- `portfolio-data.ts`와 `src/lib/investment-demo.ts`에서 샘플 저장소를 분리했다. 인사이트는 현재 보유 데이터로 계산하며 상세 질문은 기존 전역 금융 비서를 연다.
- README와 API 계약에 진입 경로, 요청 버전, 정정·취소와 시세 이력 조회 방식을 기록했다.

## 원장·평가 방식

- `20261126131217_investment_workspace.sql`은 기존 투자 계좌와 투자 이벤트를 재사용한다. 새 테이블 `investment_revisions`에는 원본 ID별 거래 버전과 요청 키를, `investment_quotes`에는 자산·통화별 시세와 기준 시각·출처를 보관한다. 두 테이블 모두 소유자 RLS를 적용하고 쓰기는 인증된 RPC로 처리한다.
- 정정·취소 후 영향받는 계좌를 시간순으로 다시 계산한다. 이후 매도 수량이나 출금 잔액이 부족하면 저장 전체가 롤백된다. 기존 거래 API도 정정된 보유 수량과 매입 원가를 읽는다.
- `src/lib/investment-book.ts`에서 소수 8자리 고정소수점으로 계산한다. 주식 취득 원가에는 매수 비용과 거래 환율이 포함된다. 매도 순수입에서 매도 수량에 배분된 이동평균 원가를 빼 실현손익을 계산한다. 배당은 비용·세금 차감 후 별도 집계한다.
- 환전은 두 통화를 함께 갱신한다. 외화 이동 시 원가를 받는 계좌로 옮긴다. 원가가 없는 외화 입금은 환차손익을 보류한다. 총 평가액은 주식·ETF 평가액과 외화 현금 평가액의 합이며 원화 대기 자금은 제외한다. 기존 생활비 원장에 투자 원금을 전기하지 않는다.
- 원가 대비 수익률과 보유 기간 수익률을 분리했다. 후자는 보유 구성이 유지된 구간에서 모든 보유 자산의 비교 가능한 시세·환율이 두 시점 이상 있을 때 계산한다. 주식은 해당 기간 순배당을 포함한다. JPY 기준 환율은 화면에서 100엔 단위로 표시한다.

## 시세와 운영 범위

- 입력한 실제 관측값만 이력과 차트에 사용한다. 기본 조회는 자산별 마지막 시세, 종목 상세는 해당 종목 이력, 분석은 기간 비교용 이력을 읽는다. 마지막 가격과 환율의 기준 시각을 각각 확인할 수 있다.
- 설정된 자동 공급자가 없어 국내외 거래소·환율 서비스에는 접속하지 않는다. `src/lib/investment-market.ts`에 공급자 인터페이스와 서버 프로세스 단위 15분 재시도 제한을 두었다. 외부 제공자 도입 시 시장별 데이터 사용 조건, 지연 분류, 거래소 달력과 다중 서버 간 한도 공유를 추가 확인해야 한다.
- 운영 프로젝트 마이그레이션 적용과 실제 로그인 사용자의 브라우저 검증은 별도다. 검증에는 샘플 데이터와 격리 DB를 사용했다.

- `scripts/test-investment-book.mjs`에서 수량, 원가, 수수료·세금, 배당, 주식 실현손익, 환차손익, 기간 수익률, 계좌 이동, 원가 미등록, 정정·취소, 초과 매도와 중복 합산 방지를 확인했다.
- `npm run db:verify`에서 마이그레이션 28개와 SQL 테스트 30개, 논리 백업 복원 및 복원 후 사용자 격리를 통과했다. `030_investment_workspace.sql`에서 시세 이력 조회, 사용자 격리, 재시도, 취소 롤백과 기존 API를 통한 매도 원가도 확인했다.
- Edge의 격리된 브라우저에서 샘플 홈 진입, 종목 상세·기간 선택, 분석·금융 비서 연결, 매수·매도·배당, 수동 시세 입력, 입금 정정·취소, 계좌 이동과 환전을 확인했다. 거래 취소 후 총 평가액이 원래 값으로 돌아왔고 페이지 재조회 후 거래가 유지됐다.
- 1440px, 768px, 390px에서 페이지 가로 넘침을 검사했고 모바일 상세 패널을 열었다. 홈·거래·샘플 예산·정기 결제의 기존 경로도 정상 응답했다.
- TypeScript 검사, 전체 ESLint, Next.js 프로덕션 빌드가 통과했다. 최종 빌드를 실행한 Edge에서도 두 브라우저 검증을 다시 통과했다. 100 USD 입금을 80 USD로 정정한 뒤 취소했을 때 샘플 총 평가액이 최초의 12,803,988원으로 복원됐다.
